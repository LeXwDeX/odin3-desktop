# 充电息屏与风扇策略所有权调查

日期：2026-09-07。调查应用基线：`3331361` / v0.1.3。

## 最终决策与实现

用户在确认原厂开关后自行将其关闭，并明确要求移除应用“智能抢占”功能。应用不再实现自动关扇或系统控制器接管：

- 删除自动风扇设置页、Dock 风扇 X 键开关、自动状态配色及多语言说明；剩余设置页按 1–6 顺序导航。
- 删除 FanWatchdogService、专用 AppMonitorAccessibilityService、开机接收器及对应权限/资源；AFK 浮层及通知仍按用户操作启停。
- 删除温控决策、自动关扇所有权、恢复与充电/前台变化监听；保留手动 OFF/SMART/MAX、RPM/PWM、温度显示以及既有用户性能切换联动。
- 应用启动时只清理旧 `auto_fan_control_enabled` 偏好和 `odin_channel_fan` 通知渠道，不发送风扇恢复命令，不改变用户的原厂充电开关。
- 数据库、分类、游戏、存档和原厂温控保护不变。此次没有 Root、修改固件或替换系统风扇组件。

验证包含真实 Application 在 Android 12L/15 下处理旧版启用偏好、通知渠道和无服务启动的测试，手动协调/输入队列/Home 回归，以及 `tools/fan-feature-removal-regression.py` 对设置、服务与遗留入口的检查。构建/替身通过不等于新版实机或整夜充电验收；设备在调查时安装的仍为 v0.1.3。

本地结果：`:app:testDebugUnitTest` 编译成功且 24 项测试通过（包含 4 项删除/升级检查）；手动风扇协调 48 项检查与温度读取回归通过；实际 Kotlin 队列的快速输入、并发读回、失败修正及 Home/Back 回归通过。将性能命令改回执行时重算的负对照按预期失败。架构/数据保留及 242 项多语言键契约通过。完整 Release 构建、签名和发布由 GitHub 工作流执行。

以下为作出上述决策前的诊断证据。

## 用户要求与范围

- 睡眠指按电源键后的系统息屏，不是 AFK 遮罩。
- 在温度及游戏等规则允许时，应持续保持关扇；用户主动改档应优先，不能把系统自动变化误认为用户意图。
- 如果仍使用前台服务，通知卡片可以保留，但不得响铃或弹窗。
- 用户明确反对两个控制循环反复争抢档位，因此增强应用守护的候选修改已撤回，先调查原厂策略是否可以成为唯一所有者。
- 本轮获准连接设备调试，不包含 Root、替换系统包、刷机或关闭温控保护。用户报告的一次短暂手动风扇操作不作为自主改档证据。

## 已复现的应用错误

`FanWatchdogService.evaluateFanPolicy` 在桌面不可见时依赖无障碍服务提供前台包名。`AppMonitorAccessibilityService` 在失去可识别窗口时清空包名；`FanControlCoordinator.policyTarget` 将未知前台作为退出自动关扇的条件。如果此前由策略关扇，它会恢复智能档。

因此，已确认空闲桌面 → 策略关扇 → 系统息屏且窗口消失 → 前台未知，可以在温度保持 50°C、持续供电且没有游戏的情况下，从 OFF 变成 SMART。

移除前在 v0.1.3 基线上运行的诊断用例：

```sh
JAVA_HOME=/opt/homebrew/opt/openjdk@17 python3 tools/fan-sleep-regression.py
```

脚本使用完整生产版 Kotlin 服务和 Java 协调器，替换 Android 窗口、时钟、温度和硬件 I/O。需要本机已有相应 Gradle 依赖缓存；其他环境应设置自己的 JDK 17 路径。在上述基线上预期以非零退出码报告：

```text
BUG: charging + 50C + no game + power-button sleep changed OFF to 4
```

这是旧功能缺陷的红色复现；相关服务现已移除，不加入现有 CI 的通过门槛，也不证明设备长时间挂起、OEM 调度或实体 PWM 行为。真实设备当前没有运行应用守护服务，不能将此源码回归冒充本轮已在设备重现应用错误。

## 设备与原厂静态证据

- Odin3 / Android 15，固件 `Odin3_V1.0.0.187_20260616_193307_user`。
- 实际拉取 `/system/app/OdinSettings/OdinSettings.apk`；SHA-256：`fdcac92b4bc20370372090ac10a896fd7e4742c89f3a92f561c645927866cdf6`。
- 分析使用该 APK 的 dex 指令与资源，不以类名猜测行为。厂商 APK、反编译文件和完整设备输出仅保存在本机临时证据目录，不提交。

| 原厂职责 | 证据位置 | 已确认行为 |
| --- | --- | --- |
| 充电时切到智能档 | `com.ro.settings.trigger.n$a` 电池广播路径 | 充电状态为 charging/full、偏好允许、设备已配置且供电类型变化时写 `fan_mode=4`，并保存先前档位；不是每个广播都反复强制写档 |
| 充电开关 | `ChargingToAutoOpenFanPref`、`trigger.n.J/B` | 默认开启；读取原厂私有偏好，不是同名 System 设置键 |
| 息屏处理 | `trigger.n.H`、屏幕广播 | 充电开关条件成立时保留当前散热；否则停止智能循环并关 PWM，唤醒时处理恢复 |
| 智能风扇循环 | `s1.b$c$a.run` | 原厂应用内约每 4 秒读取选定 CPU 或 GPU 温区，按曲线写 PWM；这段循环未包含游戏识别 |
| Odin3 PWM 后端 | `s1.b$d` | period 为 50000，使用 `gpio5_pwm2` 的 state/duty/speed；智能分支可计算出零 duty，但 UI 是否允许配置必须分开核验 |
| 曲线编辑下限 | `FanTempControlCurveView` 构造与触摸处理 | 编辑器下限字段为 20，触摸值被限制为 20–100%；不能从原厂曲线 UI 设置低温 0% |

调查时实机 UI 确认：**Odin 设置 → USB 设置 → USB 连接充电时的风扇状态设置**为开启，说明文字为“打开时，充电状态下风扇自动切换成智能模式，否则恢复风扇”。代理仅查看，未切换；用户随后自行关闭该选项。

关闭这个偏好能去掉充电触发的一个改档来源，但不等于修复应用的息屏误判，不提供按游戏状态的停转规则，也不是完整控制器接管。本轮没有用模拟电池状态、拔插电源或修改偏好验证该触发路径，因此其行为结论来自设备原厂代码与当前 UI，不是一次实际触发后的日志结论。

## 实机息屏基线

设备实际安装 v0.1.3 / versionCode 1004。开始与结束时 `dumpsys activity services com.odin.desktop` 都为 `(nothing)`，无障碍服务列表为 `null`。供电读回 AC=true、USB=false，电池约 95–96%、状态 charging；USB 调试连接不能等同于电池报告的 USB 供电类型。

在没有应用风扇守护运行的条件下，从原厂设置页执行系统 SLEEP 键事件，间隔 1、4、8、16 秒取样（累计约 29 秒；含命令开销约 30 秒），然后在 finally 中唤醒设备：

| 取样 | 系统电源状态 | fan_mode / performance_mode | PWM state / duty / period | RPM |
| --- | --- | --- | --- | --- |
| 息屏前 | Awake | 0 / 0 | 0 / 0 / 50000 | 0 |
| 息屏各次 | Dozing | 0 / 0 | 0 / 0 / 50000 | 0 |
| 恢复后 | Awake | 0 / 0 | 0 / 0 / 50000 | 0 |

本序列没有观察到原厂自行开扇。它不覆盖电源插拔、长时间深度挂起、夜间温度变化或正在运行游戏的情况。电池 37°C 不是 SoC 温度；UI 检查后的短时 CPU 热点曾到 71.7°C，不能据此声称全程都符合低温关扇条件。

设备操作仅包含导航、焦点移动、息屏/唤醒和只读检查。每次 UI 检查均使用项目包装器停止辅助进程，最终检查辅助进程不存在。未安装 APK、未改风扇/充电开关、未停止原厂系统组件。

## 接管边界与后续决策

目前已验证的 `PServerBinder`/设置写入路径能请求档位，但没有完成策略所有权移交；原厂充电/息屏观察器、智能 PWM 循环及其他性能/游戏联动仍有自己的职责。写一次 PWM 或把轮询搬到 root 后台进程，不是单一控制器方案。

若要完整实现用户规则且去掉应用端的竞争循环，下一阶段应调查如何在原厂风扇策略层统一执行温度、游戏、供电和用户意图。不能由本轮结果直接推断已有安全的替换入口；系统级修改需要单独授权、固件绑定、备份和独立恢复验证。不得停用整个 `com.odin.settings` 包，避免影响共享的灯光、充电等功能，也不得绕开温控保护。

后续用户决策已取消完整接管路线，通知静音要求由删除整个风扇通知功能替代。旧红色复现脚本仅在本机证据目录留存，放回 v0.1.3 检出的 tools 目录才能按上述命令重放；当前回归改为检查该功能确实不存在。

## 同轮设备维护：原厂启动器

用户另行要求禁用原厂“奥丁启动器”。已核对 APK 标签 Odin Launcher、包 `com.odin.odinlauncher`、版本 `2.0(20251129_104336)`、原启用状态 default，默认 HOME 已是 `com.odin.desktop/.ui.MainActivity`。执行 `pm disable-user --user 0 com.odin.odinlauncher` 后读回 disabled-user；HOME 再次打开奥丁控制台，fan_mode/duty/RPM 保持 0。保留应用数据与系统 APK；未禁用 `com.android.launcher3`、`com.odin.settings` 或游戏助手。

恢复到原启用状态可在重新确认设备后执行 `adb -s <serial> shell pm default-state --user 0 com.odin.odinlauncher`。该设备变更不是 APK 运行逻辑，不会由新版应用替用户自动执行。
