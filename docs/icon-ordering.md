# 图标排序与全部应用

v0.1.5 支持触摸手动排序、分类展示排序及“＋ 全部应用”网格。

## 使用方式

长按任意图标进入排序状态，图标抖动。可以先点选图标，再点目标位置放下；也可以长按后连续拖动，移到左右边缘（网格为上下边缘）会自动滚动。拖动结束保存，点击“完成排序”或按 Y 退出；B 先放下已拿起的图标，再退出排序。手柄仍可用 A 拿起/放下、方向键移动。

排序状态临时展开当前分类的完整列表，使第 20 个以后的图标也能移到首页。手动编辑沿用当时看到的排列，并将当前分类的展示方式切换为手动。没有改名、重建分类或升级数据库 schema。

普通滑带保留前 20 个应用，只有超过 20 个时才在第 21 个位置出现“＋ 全部应用”。它打开所有已安装、可启动应用的网格，包括前 20 个与其他分类中的应用；不是仅显示剩余图标。网格与“全部应用”分类共用顺序，返回恢复来源分类及“＋”位置。网格支持触屏、四向手柄导航、A 启动、Y 排序和 B 返回。

右下角“排序”或 START 打开排序菜单：

| 选项 | 顺序与数据来源 |
| --- | --- |
| 手动排序 | 保留完整手动位置；全部应用中的新安装应用仍置于已保存顺序之前 |
| 安装时间 | Android `PackageInfo.firstInstallTime`，最近安装优先；应用更新不会改变首次安装时间 |
| 最后运行时间 | Android `UsageStats.lastTimeUsed`，最近使用优先；读取系统保留的近一年统计 |
| 应用名称 | 当前应用界面语言的 `Collator` 排序，不区分英文大小写，同名按包名稳定排列 |

时间相同按名称排列。没有使用记录的应用置后，按名称排序；系统权限未开放或服务不可用时显示提示，并提供系统“使用情况访问权限”入口。不会自行授予权限，也不会以安装时间或一次点击推断最后运行时间。系统可能已清理旧记录，未返回记录不等于从未启动。

排序选择按分类 ID 保存在 `app_display` 偏好中；手动位置继续使用 Room 的 `app_mappings`。手动写入串行执行，待写入时保留用户当前顺序，避免数据库旧通知覆盖新操作。分类已有的新增、删除与陈旧拖动保护仍在事务中执行。

API 依据：[Android UsageStats](https://developer.android.com/reference/android/app/usage/UsageStats)、[UsageStatsManager 权限与统计](https://developer.android.com/reference/android/app/usage/UsageStatsManager)、[Compose 手势](https://developer.android.com/develop/ui/compose/touch-input/pointer-input/understand-gestures)。

## 验证

本地 Debug/Release 构建、`testDebugUnitTest` 的 30 项测试、Home/返回键和多语言架构回归全部通过。Lint 为 0 错误、50 警告；260 个中英日文案键与参数一致。新增排序模型测试覆盖 0/19/20/21/50 个图标、时间与名称并列、记录缺失和跨第 20 个位置移动。真实 ViewModel 与 Room 测试覆盖点选/拖动后完整保存、应用没有被启动、分类排序独立保存、网格手柄导航以及返回来源位置。

2026-09-07 在 Odin3 / Android 15 上以实际安装的 29 个应用检查：长按进入排序且前台仍为桌面，触摸选位能把第一个图标移到第三个，连续长按拖拽能移回；保存后重开桌面原顺序仍在。手柄右移到第 21 个位置显示“＋”，A 打开完整网格，START 打开菜单，名称、最后运行和安装时间排序均能实际切换。设备已有使用情况访问权限，最近运行列表使用系统返回数据。网格按行导航可滚动到后续应用，B 返回“＋”位置。验收前后数据库比对：3 个分类记录与 16 条应用归属及其排列顺序一致。

测试使用实际安装应用，没有向用户分类添加测试图标。旧 APK、测试前数据库/偏好备份、构建结果与原始截图位于本机忽略目录 `.android-local/device-analysis/icon-order/`，不进入 Git。正式 Release 的安装校验结果见 [发布记录](releases.md)。
