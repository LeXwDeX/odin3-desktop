# 快捷控制与下拉入口记录

2026-09-04，开发目标为 AYN Odin 3 / Android 15；下文上一版设备验证使用 `a782c9a1`。本轮新版 Dashboard、Dock 硬件后端及滤镜手柄流程尚待实机验收。

后续方向已由用户确认：先完善功能，最后统一迁移到桌面控制台。本文记录的下拉磁贴仍是当前测试入口，不是最终产品入口；本轮不撤掉已安装的测试磁贴。开发顺序见 [需求约定](../REQUIREMENTS.md#开发顺序与最终入口)。

## 当前交互

- 系统下拉面板原“游戏助手”位置改为“滤镜开关”，右侧紧邻“息屏挂机”。短按滤镜开关切换当前应用，长按打开截图调参。
- 不要求选择应用或图形 API。截图全屏显示，右侧参数栏可收起，支持更换截图和即时 GPU 预览。
- 方向键移动控件焦点，A 执行当前项。滑条需要先按 A 进入调节，再左右修改，A 确认；B 取消本次调节并恢复进入时的值。
- 选择弹层方向键选项、A 确认、B 取消。B 按当前所在层依次关闭选择弹层、取消滑条调节、收起高级参数、隐藏参数栏，最后退出页面；不会一次越过多层。
- 按住 X 显示原图、按住 Y 隐藏参数，松开各自恢复；选择弹层内也可使用，失焦或离开恢复临时状态。L1/R1 仅在主层参数栏可见且高级参数未展开时切换预设，不在滑条调节或选择弹层内切换。
- 没有游戏目标也能调整全部截图参数，独立保存到 `shader_screenshot_preview`；只有“应用到游戏”开关禁用。有目标时读取和保存该应用的配置。
- 挂机使用黑色 OLED 浮层，双击退出；不是 Android 电源键的物理熄屏。浮层不占用游戏手柄焦点。
- 当前实时接入仅支持 CRT 兼容遮罩；其他组合可在截图预览，完整实时效果和跨进程图形 API 识别仍需原生接入。详见 [滤镜移植记录](shader-port.md)。

Dashboard 统计卡片只读，常用操作只有文件管理、系统设置、Odin 设置、滤镜调整四项；已取消内存清理和磁盘清理。CPU/GPU 只采集真实温度，以数值和固定 0–105°C 温度条显示；不采样使用率。内置与每个已挂载外部卷分开显示，详见 [Dashboard 说明](dashboard.md)。

## Dock 与风扇充电模式

性能/风扇联动与 Home、返回键连按问题已追加修复，见 [本轮修复与实机证据](performance-fan-home-fixes.md)。手动最大跨性能档位保持；传感器开关不再随性能切换丢失；按键即更新用户选择，后台执行最后一次意图，失败再校正，未知硬件状态不显示成关闭。

Dock 保留五个等宽卡片，方向键选择、A 操作，触摸主卡片同样可用。硬件状态以读回值为准，失败时提示错误，不因按钮被按下就报告切换成功。

| 项目 | A 操作 | 附加显示或操作 |
| --- | --- | --- |
| 性能 | 循环默认、性能、高性能 | 显示当前档位 |
| 风扇 | 循环关闭、智能、高性能 | 聚焦时 X 切换充电模式；触摸副行同样可切换 |
| 摇杆灯 | 开关 | 两组灯状态写入后确认 |
| 充电限制 | 同时切换 80% 上限和 5V 档 | 主副行分别显示两项读回状态；两项未同时开启时下一次尝试同时开启 |
| 飞行模式 | 开关 | 权限或读回失败时提示 |

5V 档是充电限制设置，实际电流由电源与充电协商决定，不显示为实测 3A。

手动切换风扇先关闭充电模式，避免服务覆盖手动选择。只有充电模式开启、正在充电、前台已识别且不是游戏、性能为默认、CPU/GPU 温度有效且最高不超过 60°C 时，策略才允许停转。温度读取失败不能自动关风扇；超过 60°C 时保留智能散热，已有高性能风扇档保持。取消策略或结束服务不恢复旧启动档位。失败请求串行处理并退避重试，不替代 OEM thermal 服务。

## 受限硬件后端

当前应用直接调用 Odin 3 固件注册的 `PServerBinder`，性能、风扇、灯光、充电和飞行模式均在应用内完成。没有电脑启动的桥接进程、网络连接或配对步骤。调用方仍使用应用 UID；原厂服务以其固件身份执行固定操作。

共享事务引擎保留白名单、性能与风扇联动、实际属性/PWM 核验和失败回滚。飞行模式通过系统 `cmd connectivity airplane-mode` 正式命令切换。服务暂不可用或读回失败会返回错误，不能凭调用返回成功判定硬件生效。调查与验收见 [原厂服务接入记录](hardware-standalone-investigation.md)。

旧 `127.0.0.1:18889` ADB 桥保留为开发诊断工具，当前 APK 已移除桥客户端和其联网权限。以下 2026-09-04 的桥接、配对和限制属于历史版本。

## 上一版截图预览问题复核（2026-09-04）

- 亮度 `+100` 会把输入裁剪为白色，再叠加 CRT；将亮度恢复为 `0` 后，取样区域与调节前逐像素一致。此项只解释过曝，不能据此排除用户另行反馈的绿色竖纹。
- 修复菜单 CRT 在截图保持比例缩放时的坐标适配：相位改用屏幕物理像素，不再使用经过缩放的源图 UV 乘整屏分辨率。326 × 265 截图在 1920 × 1080 屏幕留黑边时，原横向每两像素的平均偏差为 16.49/255；修复后真实 CRT 明暗调制仍在，横、纵每两像素偏差均为 0。强度系数保持不变。
- 同一纯白 CRT 对照区域在修复前后均为 `R=G=B`，设备表面为 RGBX8888。用户肉眼观察到的绿色竖纹是否消失仍需实屏确认，不能用截图无绿色替代该结论。
- 只读 GPU 对照证实：缩放为“无”时锐度 1/5 输出相同；FSR 保持比例、其他效果关闭时，锐度 1/5 在取样区改变约 57.97% 像素，平均通道差约 2.19/255。当前 Vulkan 家族锐化较轻；开启 FXAA 会按上游顺序从源图重算并覆盖此前锐化。
- 锐度行现在按适用模式启用，并提示未生效原因。实机“无”模式显示“选择 FSR 缩放后生效”，滑条禁用但保留用户档位 5；其他参数可调。FSR / FSR 保持比例和 Vulkan DLS 使用锐度，Vulkan FXAA 覆盖时提示说明。安装前后截图、独立参数和游戏数据库均未改变。
- 上述 GPU 对照通过独立预览参数运行，未修改用户截图或保存的调参配置。证据和修复前 APK/配置备份位于本机同级 `shader-green-lines/`，其中 `verification.json` 记录当前验证边界。

## 上一版原厂游戏助手停用记录

先核实包名、系统服务边界与恢复方式，再执行：

```sh
adb -s a782c9a1 shell pm disable-user --user 0 com.odin.gameassistant
adb -s a782c9a1 shell am force-stop --user 0 com.odin.gameassistant
```

该包是系统 persistent 应用，普通强停后旧服务仍存活。经用户允许继续设备操作，在截图参数保存后进行了正常重启。重启后 `enabled=3` 保持；`ForegroundAppMonitorV4Service`、`AppConfigService`、`FloatingViewService` 全部不存在，WMS 无该包的浮窗记录。

系统仍创建该包的 persistent Application，保留屏幕开关接收器和 mapping 服务绑定，不能称为完全零后台。当前 `is_quick_set_performance_and_fan_enable=1`，已核验的接收器逻辑跳过风扇写入。停止这层助手也停止其按游戏切换的性能、风扇和按键预设；未删除其 APK 或数据。

当时独立的 SettingsController、power、thermal 服务正常；thermal HAL 已连接、状态 0。采样时风扇模式 4、PWM state 1、duty 12500，我方 AppMonitor 和 FanWatchdog 在运行。该次历史采样没有观察到旧 18888 daemon 监听；这不涉及本轮新增的 18889 受限桥，不能作为新后端的验证结果。

恢复原包的默认启用状态：

```sh
adb -s a782c9a1 shell pm default-state --user 0 com.odin.gameassistant
```
