# 图谱验证流程

代码结构发现优先使用 `codebase-memory-mcp`。会话开始或压缩恢复后，通过 `list_projects` 或 `index_status` 确认最近的图谱项目、仓库路径和索引代次，再选择证据等级。项目未索引时先调用 `index_repository`。

## 工具顺序

1. `search_graph`：按模式查找函数、类、路由和变量。
2. `trace_path`：追踪调用方或被调用方。
3. `get_code_snippet`：用搜索得到的完整符号名读取准确源码。
4. `check_index_coverage`：在作出结论前核对候选路径及缺失范围。
5. `query_graph`：查询复杂关系。
6. `get_architecture`：查看高层项目概要。

搜索字符串、错误消息、配置值或非代码文件时可直接用 `rg` 和文件读取；图谱结果不足时也应回退到源码检索。

## 证据等级

- **Scout / Tier 1**：少量调用与定向源码核验，仅作临时的正向发现，不作否定或穷尽结论。
- **Verify / Tier 2（默认）**：面向当前任务查询，追踪相关调用方向，对重要结论读取准确源码，完成相关结果的分页。
- **Auditor / Tier 3**：在明确范围内使用当前索引代次，完成全部相关分页；调用双向及更广关系影响结论时一并验证，并披露所有限制。

发现候选路径后，将本次依赖的所有文件一起传给 `check_index_coverage`。否定或穷尽结论还需检查相关目录范围。干净结果仅表示没有已记录缺口，不证明完整性。

遇到部分解析、跳过、排除、过时、待索引或覆盖未知时，在依赖图谱结果前直接读取或检索报告中的行范围或目录，并注明剩余限制。结果包含 `has_more`、`next` 或 `nextCursor` 时，完成与结论相关的分页。

## 委派时传递证据

需要委派时，父代理先查询图谱并检查覆盖，再向子代理提供：证据等级、项目、索引代次与新鲜度、任务范围、查询及分页状态、完整符号名、文件路径、调用链结论、覆盖缺口的行号和原因、已完成的源码核验以及未解决的问题。

不假设子代理继承了 MCP 工具或完整对话。缺少 MCP 工具的子代理使用父代理提供的证据，直接读取或检索准确源码，尤其是覆盖缺口；不调用或声称使用了不可用的 MCP 工具。
